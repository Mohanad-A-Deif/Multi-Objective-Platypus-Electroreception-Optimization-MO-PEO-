# MO-PEO — Code, Results and Figures

This repository contains the complete implementation, experiment scripts, and output data behind
**"Multi-Objective Platypus Electroreception Optimization (MO-PEO): A Pareto-Based Extension with
Localised Perturbation and Deferred Refinement"**, the multi-objective extension of the single-objective
**Platypus Electroreception Optimization (PEO)** metaheuristic (Deif & Khishe, *Cluster Computing*, 2026).

No manuscript text is included here. This is the code-availability companion to the paper: everything
needed to reproduce every number, table and figure it reports.

There is no external dataset. Every benchmark problem (ZDT1–ZDT6, DTLZ1–DTLZ7) is generated
analytically by `code/problems.py`, and the radiotherapy case study's synthetic phantom and dose model
(`code/phantom.py`, `code/dose_model.py`) are generated by the code itself at run time. What would
otherwise be "data" ships here as the code that produces it, plus the already-computed output files
under `results/` so the reported numbers can be inspected without a full rerun.

## Repository layout

```
code/       All Python source: problem definitions, MO-PEO and the five competitor algorithms,
            the radiotherapy case study, calibration/diagnostic scripts, table and figure generation.
results/    Stored numerical output (JSON/pickle) backing every table in the paper, plus the
            pre-registered calibration and diagnostic logs described below.
figures/    The nine PNG figures used in the paper, generated by code/make_figures.py and
            code/make_rt_figures.py.
```

### `code/`

| File | Role |
|---|---|
| `problems.py` | ZDT1–ZDT6 and DTLZ1–DTLZ7 definitions, reference (Pareto) fronts, Das–Dennis weights, non-dominated sorting, crowding distance. |
| `algorithms.py` | MO-PEO's sibling single-objective-style helpers (`weights`, `trunc_archive`), SBX+polynomial mutation, NSGA-II, MOEA/D. |
| `mopeo4.py` | MO-PEO itself (the reported algorithm and its ablations: `sparse`, `mode`, `rspeed`/τ parameters). |
| `mopeo5.py` | The two alternative diversification designs discussed in the appendix (S1 split-density, S2 spatial `p_rel`). |
| `mopso.py`, `gde3.py`, `mogwo.py` | The three additional competitor algorithms, implemented and validated from scratch (no external optimisation library is used anywhere in this repository). |
| `metrics.py` | IGD and hypervolume (exact, closed-form; no external metrics library). |
| `reproduce.py` | Single entry point: `python reproduce.py` reruns every stage end to end (~35 min, one core) and is resumable; `python reproduce.py --list` shows all stages. |
| `calibrate_tau.py`, `tau_diag.py`, `analyse_tau.py`, `analyse_tau_calib.py` | The pre-registered calibration of the deferred-refinement threshold τ, and the earlier exploratory sweep. |
| `diag_dtlz4*.py`, `analyse_dtlz4*.py` | The DTLZ4 failure-diagnosis study (appendix). |
| `probe_mopso.py`, `validate_baselines.py` | The MOPSO hyperparameter grid search, and validation of every competitor against its published source. |
| `rt_problem.py`, `rt_algorithms.py`, `dose_model.py`, `phantom.py`, `rt_calibration.py`, `run_rt.py`, `make_rt_figures.py` | The bi-objective, constrained radiotherapy case study: synthetic phantom, beamlet dose model, the six constrained-domination variants of every algorithm, and its figures. |
| `mktables.py`, `mktables_supp.py`, `make_figures.py` | LaTeX table and figure generation from the files in `results/` (kept here for completeness; the manuscript itself is not part of this repository). |
| `stats_six.py`, `audit_repro.py` | Friedman/Wilcoxon/Holm statistical summary, and a standing bit-for-bit reproducibility audit of every stored result against the current code. |
| `style.py` | Shared matplotlib style settings (greyscale, serif, inward ticks — used by every figure script). |

### `results/`

The main files: `results_final.json` (20 runs × 12 problems × every algorithm/ablation variant: IGD and
hypervolume per run), `tau_calib.*` and `tau_calib_protocol.json` (the pre-registered τ calibration:
seeds 6000–6039), `tau_diag_*.pkl` (the earlier exploratory τ sweep behind the supplementary table),
`diag_dtlz4*.*` (the DTLZ4 failure diagnosis, seeds 7000–7039), `dtlz4_dose*.*` (the perturbation-density
dose-response sweep), `probe_mopso*.json` (the MOPSO grid search), `rt_run.json`/`rt_run.md` (the full
radiotherapy case study: all six algorithms, 20 seeds, feasibility and violation trajectories),
`stats_six.*` (the Friedman/Wilcoxon/Holm statistical tests), `audit_repro.json`/`.md` (a bit-for-bit
reproducibility check: every stored result re-run at its first seed and compared against the code in
this repository — see below), and `validation_new.json` (MOPSO/GDE3/MOGWO validated against their
published sources). `ref_fronts.pkl`, `fronts_med.pkl` and `conv.pkl` are cached intermediate data
(reference fronts, median-run fronts for the front plots, and convergence-vs-budget curves) that let the
figure scripts run without recomputation.

### `figures/`

The nine figures used in the paper, generated by `code/make_figures.py` (figures 1–5, A1) and
`code/make_rt_figures.py` (the radiotherapy figures and calibration plot).

## Reproducing the results

```bash
cd code
python reproduce.py --list              # show every stage
python reproduce.py                     # everything, ~35 min on one core
python reproduce.py --stage main        # just the main 12-problem, six-algorithm comparison
python reproduce.py --stage audit       # bit-for-bit reproducibility check against results/
python run_rt.py                        # the radiotherapy case study (separate entry point)
```

All seeds are fixed (`1000 + run index` for the main protocol; see the module docstrings for the
calibration, diagnostic and tuning seed ranges, which are deliberately disjoint from the protocol
seeds). Every stage is resumable: results are checkpointed after each (problem, algorithm) pair, and a
rerun skips whatever is already complete.

## Requirements

Python 3, with `numpy`, `scipy` (statistical tests and figure smoothing only) and `matplotlib` (figure
generation only). No other third-party package is required or used anywhere in this repository — every
algorithm (NSGA-II, MOEA/D, MOPSO, GDE3, MOGWO and MO-PEO itself) is implemented from scratch in NumPy,
and IGD/hypervolume are computed in closed form without an external metrics library. The exact package
versions used to produce the numbers reported in the paper were not recorded; any reasonably current
version of the three libraries above is expected to reproduce them, since every stochastic routine is
seeded explicitly through NumPy's `Generator` API.
